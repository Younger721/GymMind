## 1. 项目目标

建设一个 PC 优先、兼容平板的个性化智能健身 Web 系统，形成以下可演示闭环：

```text
用户画像 → 上传/搜索健身知识 → 个人知识库 → RAG 问答
    → 训练计划/饮食计划 → 执行与记录 → 数据分析/周报 → 调整建议
```

系统的核心价值是把个人知识、用户档案、训练记录和饮食数据结合起来，提供有来源、可解释、可追踪的健身辅助建议。

## 3. 范围与优先级

### 3.1 MVP：必须完成

- 用户注册、登录、JWT 鉴权、退出登录、修改密码
- 用户健身档案：身体数据、目标、经验、训练频率、器械、饮食偏好和忌口
- 个人知识库：至少支持 PDF、TXT；后续补充 Markdown、Word
- 文档解析、清洗、分块、Embedding、pgvector 存储、处理状态和失败重试
- 文档分类、列表、搜索、来源查看、删除和严格的用户数据隔离
- RAG 健身问答，回答尽量提供真实来源；无可靠依据时明确说明
- 合法联网搜索，用户确认后将文章或论文导入个人知识库
- 健身动作库和第三方视频链接推荐，不下载或托管第三方视频
- AI 训练计划生成、展示和基础规则校验
- 训练记录、训练容量、最大重量、PR 和基础统计
- BMI、BMR、TDEE、目标热量和宏量营养素计算
- AI 饮食规划、饮食记录和摄入对比
- Dashboard 首页和基本进度图表

### 3.2 第二阶段：加分功能

- 长期记忆、用户偏好和用户目标的结构化存储
- ECharts 完整趋势分析和肌群分布
- AI 训练分析和 AI 健身周报
- 个性化文章、视频和饮食推荐

### 3.3 第三阶段：展望功能

- 主动提醒和训练问题发现
- 自动调整训练计划
- 知识图谱、MCP、多 Agent、健身社区

第三阶段功能不作为 MVP 的完成前提。毕业设计优先保证主闭环稳定，避免为了展示复杂概念引入不可控的 Multi-Agent 依赖。

## 4. 技术基线

| 层次 | 选型 |
|---|---|
| 后端 | Java 17+、Spring Boot 3、Spring Web、Spring Security、Spring Data JPA、Spring AI、Maven |
| AI | OpenAI Compatible API；支持 DeepSeek、Qwen 或 OpenAI；Embedding 模型可配置 |
| 数据 | MySQL 8.0（本地复用）、Redis |
| 向量检索 | **Milvus v2.4.17**（语义向量检索）+ **Elasticsearch 9.4.2**（全文检索、元数据过滤）双重索引 |
| 文件 | MinIO（对象存储，同时作为 Milvus 依赖） |
| 文档解析 | PDFBox、Jsoup；Word/Markdown 根据实际实现补充解析器 |
| 前端 | Vue 3、Vite、TypeScript、Element Plus、Pinia、Vue Router、Axios、ECharts |
| 部署 | Docker Compose；开发环境提供最小化启动说明 |

架构边界：Controller → Application Service → Domain/Rule Service → Repository。AI 调用统一经过 `AiGateway`，RAG 检索由 `RagOrchestrator` 编排（Milvus 向量检索 + ES 全文检索混合召回），训练容量、BMI、BMR、TDEE、营养素和统计口径由后端确定性计算。

**状态：已完成 90%（待测试验证）**

### 阶段 2：个人知识库与文档处理（第 2-3 周）

目标：完成”上传资料 → 异步处理 → 向量入库”的流水线。

- [x] 实现 PDF、TXT 文件类型和大小校验
- [x] 实现文档上传、MinIO 存储和文档元数据保存（MySQL）
- [x] 实现 `PENDING/PROCESSING/SUCCESS/FAILED` 文档状态机
- [x] 实现 PDF/TXT 文本解析和清洗
- [x] 实现可配置的 Chunk 切分策略（滑动窗口、语义分块）
- [x] 生成 Embedding 并**双写**到 **Milvus**（向量）和 **Elasticsearch**（全文+元数据）
- [x] 在 Milvus 中创建 Collection，配置向量维度、索引类型（HNSW/IVF_FLAT）和度量方式（COSINE/IP）
- [x] 在 ES 中创建 Index，配置中文分词器（smartcn）、字段映射和 userId 分区策略
- [x] 实现文档列表、分类、关键词搜索（ES）、来源查看和删除
- [x] 实现失败原因展示和重新处理
- [x] 为每个 Chunk 保存 `userId/documentId/documentName/sourceType/sourceUrl/category/createdAt`
- [ ] 增加跨用户读取、删除和向量检索隔离测试（Milvus 和 ES 都需验证 userId 过滤）

验收：上传文档后可以看到处理状态；成功文档可检索；失败文档可重试；用户 A 无法看到用户 B 的文档和 Chunk。

**状态：已完成 95%（待测试验证）**

### 阶段 3：RAG 智能问答（第 4 周）

目标：完成带用户画像和来源引用的最小 RAG 链路。

- [ ] 实现问题意图分类的最小版本
- [ ] 查询当前用户的目标、身体数据和训练偏好
- [ ] 实现**混合检索策略**：
  - **向量召回**：通过 Milvus 进行语义相似度检索（Top-K1）
  - **关键词召回**：通过 ES 进行全文匹配和布尔查询（Top-K2）
  - **融合排序**：使用 RRF（Reciprocal Rank Fusion）或加权分数融合
  - 所有检索必须按 `userId` 过滤，确保用户数据隔离
- [ ] 实现 Rerank（可选）：使用 BGE-Reranker 或 Cohere Rerank API 对召回结果重排序
- [ ] 实现去重和上下文长度控制
- [ ] 接入 `AiGateway`，统一处理超时、重试和模型错误
- [ ] 根据实际检索 Chunk 生成引用，不允许模型自行伪造来源
- [ ] 无足够依据时返回明确的无依据提示
- [ ] 记录请求次数、输入 Token、输出 Token、总 Token 和响应耗时
- [ ] 建立 10-20 条固定问题的 RAG 评测集

验收：用户可以针对自己的资料提问；回答带可回溯来源；跨用户知识不泄露；模型失败时有可读降级提示。

### 阶段 4：联网搜索与知识导入（第 5 周）

目标：实现“搜索 → 用户选择 → 合法入库”的知识发现闭环。

- [ ] 接入一个合法的普通搜索 API
- [ ] 接入 Semantic Scholar 或 Crossref 之一
- [ ] 展示标题、摘要、来源、URL、发布时间和相关度
- [ ] 提供“阅读原文”和“加入我的知识库”操作
- [ ] 仅处理公开页面，使用 Jsoup 提取正文并限制超时、响应大小和频率
- [ ] 保存 URL、标题、作者、发布时间和来源类型
- [ ] 复用文档处理流水线完成清洗、切块和向量化
- [ ] 搜索结果与知识入库分离，不自动全量导入
- [ ] 对登录限制、付费内容、反爬失败和版权限制返回明确状态

验收：用户能选择一条搜索结果导入知识库；导入后可在 RAG 中检索；系统不绕过权限、不下载受授权内容。

### 阶段 5：动作库、训练计划与训练记录（第 6 周）

目标：打通训练建议到训练执行记录。

- [ ] 建立动作和视频资源基础数据

- [ ] 实现训练记录：日期、动作、重量、次数、组数、RPE、时长和备注
- [ ] 实现训练次数、总容量、最大重量、PR 和周/月统计

验收：用户可以生成一周计划并记录一次训练；容量和 PR 可由同样输入重复计算得到；AI 输出格式错误时返回模板化结果。

## 7. 验收标准

### 功能验收

- [ ] 注册、登录、JWT、退出和改密可用
- [ ] 用户档案可维护，并用于 AI 个性化上下文
- [ ] PDF/TXT 能上传、处理、检索、删除和失败重试
- [ ] RAG 回答能展示真实来源，无依据时不伪造引用
- [ ] 搜索结果需经用户确认后才能入库
- [ ] 训练计划、训练记录和统计可用
- [ ] 营养计算可复现，饮食计划和饮食记录可用
- [ ] 视频链接跳转原始平台，不托管视频
- [ ] Dashboard 能展示关键数据

### 非功能验收

- [ ] 任意用户不能读取、修改、删除其他用户的私有数据
- [ ] 所有向量检索都带用户过滤条件
- [ ] AI 输出经过 JSON Schema 或 Bean Validation 校验
- [ ] 每次 AI 调用都有 Token 和耗时日志
- [ ] 文件和网页处理有大小、类型、超时和失败状态控制
- [ ] 医疗或特殊人群问题有风险提示
- [ ] Docker Compose 能启动核心依赖并完成本地演示

## 9. 风险与处理策略

| 风险 | 处理策略 | 负责人/状态 |

| 项目范围过大 | 先锁定 MVP，扩展项后置 | 项目负责人 / 进行中 |

| 网页版权和反爬 | 仅合法 API 和公开正文，遵守 robots/条款并限频 | 项目负责人 / 待开始 |
| 营养和医疗风险 | 一般性建议、风险提示、高风险问题转专业人士 | 项目负责人 / 待开始 |
| 模型成本和时延 | Top-K、压缩、缓存、模型分级、Token 监控 | 项目负责人 / 待开始 |
| 第三方视频失效 | 只保存原链接并显示来源平台 | 项目负责人 / 待开始 |
