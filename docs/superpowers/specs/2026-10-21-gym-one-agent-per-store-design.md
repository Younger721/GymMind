# 每家门店限制一个 Agent

## 目标

GymMind 每个门店（租户）最多配置一个 Agent。门店 AI 配置页显示 `已用数量 / 1`，平台配额配置也固定为 1。已有 Agent 继续可编辑提示词。

## 行为与范围

- Agent 数量按租户下的所有记录计算，启用和停用记录都占用唯一名额。
- 后端把每租户的有效 Agent 上限固定为 1。配额读取返回上限 1，Agent 配额校验不再信任历史配额记录中的更高值。
- 新建租户的默认 Agent 配额为 1。平台管理员不能把 Agent 配额调整到高于 1；其他 AI 调用、Token 和知识文档配额保持可配置。
- 门店配置页显示 `usedAgents / 1`。平台配额页将 Agent 上限展示为 1 且不可调整。
- 保留现有的 Agent 提示词编辑、聊天和租户隔离行为。
- 不删除或修改已有 Agent 记录。若已有租户包含多条记录，页面如实显示数量，且之后不允许再增加；本次不尝试自动合并或清理旧记录。

## 实现边界

复用现有 `TenantQuota`、`TenantQuotaView` 和 `DefaultTenantQuotaService`。在服务层统一固定 Agent 上限，并在平台配额更新入口拒绝非 1 的 Agent 上限；前端门店页和平台配额表单同步反映固定值。当前创建接口仍保持关闭状态，不新增 Agent CRUD 能力。

本次不新增数据库唯一索引，也不执行数据迁移。这样不会因历史重复 Agent 使应用启动失败，也不会触碰租户现有数据。上限在应用服务层执行；如果未来开放并发 Agent 创建，再结合现有数据检查增加数据库唯一约束。

## 验收

1. 租户配额读取对历史上限高于 1 的租户仍返回 `maxAgents = 1`，并保留真实 `usedAgents`。
2. Agent 数量达到 1 时，配额校验拒绝增加；停用的 Agent 也占用名额。
3. 平台修改配额时无法将 Agent 上限设置为大于 1；其他配额仍可正常保存。
4. 门店 AI 配置页和平台配额页都展示固定上限 1。
5. 现有 Agent 提示词编辑测试保持通过，且不会清理或改写已有 Agent 记录。
