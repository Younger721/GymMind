# 角色权限按管理员作用域配置设计

## 目标

平台管理员维护全局角色菜单默认值，健身房管理员维护当前门店的教练和会员菜单覆盖。平台管理员角色固定全量只读，健身房管理员角色固定管理权限。

## 数据与权限模型

- 保留 `sys_role_permission` 作为平台级角色模板。
- 新增 `sys_tenant_role_permission`，按 `tenant_id + role_id + permission_id` 唯一关联，并以 `role:menu:configured` 标记某个门店角色已经配置过覆盖。
- 租户用户登录时，角色存在门店覆盖则只使用覆盖权限；没有覆盖则使用平台模板。平台管理员不读取门店覆盖。
- 门店覆盖只允许 `COACH` 和 `MEMBER`，菜单边界仍由 `PermissionCatalog` 控制。

## API 行为

- `GET /api/v1/roles`：平台管理员返回全局角色，健身房管理员返回门店可管理角色及只读的 `GYM_ADMIN`。
- `GET /api/v1/roles/permissions`：返回当前操作者作用域下的菜单目录和角色关联状态。
- `PUT /api/v1/roles/{roleCode}/permissions`：平台管理员写入全局模板，健身房管理员写入当前租户覆盖；拒绝平台管理员角色、自身健身房管理员角色、普通用户和跨租户请求。

## 前端行为

角色权限路由对平台管理员和健身房管理员开放。页面根据当前作用域决定可编辑角色，平台管理员和健身房管理员固定角色只读；树节点只展示菜单权限，保存由后端展开到操作权限。

## 失败与兼容

- 未配置门店覆盖时回退全局模板，保证旧租户无需迁移数据即可继续登录。
- 空菜单覆盖通过配置标记保留，表示明确关闭全部可配置菜单，不回退模板。
- 新增表使用 Hibernate 更新或生产增量 SQL 创建，不删除或重置已有数据。
