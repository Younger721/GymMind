# AI 助手模式与训练计划设计

## 状态

设计方向已由用户确认，等待规格文档复核。

## 背景

当前前端把 Harness 聊天放在 `AssistantView.vue`，训练计划放在独立的 `PlanGeneratorView.vue`。Harness 插件负责给聊天补充 RAG 或工具上下文；训练计划则已有独立的草案生成和保存接口。两者入口分开是产品体验不统一，不代表后端必须合并成同一种流程。

训练记录已保存在 `workout_record` 和 `workout_set` 中，包含租户、会员、训练日期、完成状态、动作、组数、重量和次数。当前 repository 仅暴露写入能力，AI 草案生成尚未查询历史训练数据。

## 目标

- 在 AI 助手中提供“健身知识问答”和“AI 训练计划”两种清晰模式。
- 知识问答继续使用现有 Harness/RAG 流程；训练计划使用结构化输入、历史记录上下文、草案审核和显式保存流程。
- 训练记录由后端按当前用户权限从本地数据库查询，不依赖前端传入训练历史，也不做外部数据同步。
- 会员只能使用自己的记录；教练和租户管理员只能在本租户且符合其业务授权的范围内选择会员。
- 保持租户隔离；平台管理员没有租户上下文时不能由普通 AI 接口隐式读取租户会员明细。

## 非目标

- 不把训练计划保存改成 AI 自动执行，也不允许模型绕过训练计划服务直接写数据库。
- 不在本次设计中重写 Harness、RAG 索引、训练记录录入或租户隔离体系。
- 不新增跨租户的平台级会员明细入口。
- 不要求会员把训练历史导出或重复上传给 AI。

## 产品与交互

### 助手入口

在 AI 助手顶部提供固定的模式切换：

- **健身知识问答**：现有聊天体验，按租户配置调用知识库检索并展示引用来源。
- **AI 训练计划**：显示训练目标、每周训练次数、训练经验、每次训练时长、可选器械和可选限制等结构化表单；可补充自由描述。

模式切换后开启新的会话上下文，避免知识问答和计划生成的历史消息混用。计划生成结果显示为可审核、可修改的结构化草案；用户明确点击“保存到训练计划”后才调用现有保存流程。失败时保留表单输入，允许重试。

会员默认绑定自己的会员档案，不显示可更换会员的选择器。教练仅可从自己当前负责的会员中选择目标会员；租户管理员只有在具备会员读取和计划管理权限时，才能选择本租户会员。没有租户上下文的平台管理员仅可使用不读取会员数据的通用能力。

保留旧 `/plan` 入口作为兼容跳转，进入 `/assistant?mode=workout-plan`，不再维护两套计划生成 UI。

### 生成流程

1. 用户选中“AI 训练计划”，填写目标和训练约束，并选择允许的会员目标（仅教练/租户管理员）。界面明确提示是否会参考近期训练记录；默认启用，允许关闭。
2. 后端从认证上下文获取 actor 和 tenant。会员的目标会员 ID 从 actor 关联档案解析，不信任请求体中的会员 ID；教练/管理员目标必须经过本租户成员校验及其业务授权校验。
3. 用户启用记录参考时，后端按 tenant、member、日期和已完成状态查询最近 8 周记录，最多取 30 条，并生成精简摘要。摘要包括训练频次、训练日期、动作、已完成组数、重量/次数趋势及训练时长；默认不把原始备注、联系方式等无关个人信息发送给模型。
4. 服务端将结构化需求和摘要组合后调用模型，解析结构化结果，并由后端验证计划字段、日期、动作 ID 和业务约束。
5. 返回草案以及本次参考记录的摘要信息。没有历史记录时明确标注“暂无可参考记录”，仍允许基于表单生成。
6. 用户确认保存后，由现有训练计划服务重新校验 actor、tenant、member 和计划内容，并保存计划。

## 后端边界

- 保留现有 Harness 聊天接口处理知识问答；训练计划不作为 Harness 普通上下文插件，因为它有不同的输入契约和保存生命周期。
- 复用现有 `AiWorkoutPlanDraftService`、`/workout-plan-drafts` 与显式 `/workout-plan` 保存入口，在草案服务中增加会员授权解析及训练历史上下文组装。
- 为 `WorkoutRecordRepository` 增加按租户、会员、状态和日期范围读取记录的查询能力；为 `WorkoutSetRepository` 或对应查询端口增加批量读取关联组数据的能力，避免逐记录查询。
- 增加一个仅供计划生成使用的训练历史摘要组件。它依赖 workout repository 和动作目录，不把 workout 模块实体或持久化细节暴露给 AI API 层。
- 任何返回或生成都从 `CurrentActor` 获取 tenant。请求中的 tenant ID 不作为授权依据；对越权会员目标返回统一无权限/资源不可见错误。
- 继续使用现有租户 AI 配额和调用用量记录。训练数据查询失败时不把错误伪装成“没有训练记录”；无记录是正常空结果，数据库依赖失败则返回可重试错误。
- 模型输出只生成草案。动作必须能映射到允许使用的动作目录项；非法 JSON 或校验不通过时不保存任何数据。

## 前端状态

- 加载会员列表、加载训练记录上下文和生成计划分别呈现 loading 状态。
- 空历史状态允许继续生成，并说明这次只依据表单信息。
- 越权或目标会员失效时清除/锁定会员选择并展示权限错误，不回退到跨租户查询。
- 模型不可用或结果结构校验失败时保留表单，提供重试入口。
- 草案与已保存计划应有明确状态差异，保存成功后提供查看计划入口，防止重复提交。

## 验收与测试

### 后端

- 会员请求只能解析并读取自己的档案；伪造其他 memberId 不可读取、生成或保存计划。
- 教练只可为当前租户且已分配给自己的会员生成计划；未分配会员和其他租户会员均被拒绝。
- 租户管理员的会员选择与计划保存始终限定在认证 tenant 内；无租户上下文的平台管理员不能访问会员级训练历史。
- 训练历史查询仅包含指定 tenant/member 的最近 8 周、最多 30 条已完成记录及完成组；其他租户、取消记录、超窗记录不进入模型上下文。
- 无历史记录仍可生成；训练历史存储不可用、模型不可用、JSON 错误或动作校验失败时返回预期错误且不写入计划。
- 保存草案时再次校验授权和租户归属，不能复用生成阶段的旧授权结果。

### 前端

- 助手模式切换正确展示对应流程，切换后不混用会话消息。
- `/plan` 能进入助手计划模式；现有知识问答路由和 RAG 来源展示保持可用。
- 会员看不到会员切换控件；教练可选范围受后端限制；空数据、生成失败、保存失败均有明确状态。
- 计划仅在用户确认后保存，重复点击不会生成重复计划。

## 实施顺序

1. 添加训练记录/组的受限查询端口与授权测试。
2. 添加会员目标解析和近期训练摘要组件。
3. 把摘要注入训练计划草案生成，补充结构、动作与保存权限校验。
4. 在助手内增加模式切换和计划草案审核体验；将 `/plan` 改为兼容跳转。
5. 运行目标后端测试、前端构建和租户隔离回归测试。
