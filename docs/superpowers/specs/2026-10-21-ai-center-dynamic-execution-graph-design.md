# AI 中心动态执行流程图设计

## 背景

AI 中心当前将 Harness 通过 SSE 推送的执行进度渲染为纵向步骤列表。用户希望改成 AgentCore 协作图所采用的动态节点与连线视觉，以便在回答生成期间直观看到流程进展。

GymMind 当前已有真实的路由、知识检索、插件和 Tool 进度事件，但没有 AgentCore 式的多 Agent 并行执行拓扑。本次只改进现有事件的可视化，不改变执行语义。

## 目标

- 将现有步骤列表改为动态流程图风格，节点随着 SSE 事件到达而出现和更新。
- 明确表达 STARTED、RUNNING、COMPLETED、FAILED 状态，并显示步骤名称、简短摘要和可用结果数量。
- 保留步骤详情展开、流程整体折叠、错误状态和已保存对话中的历史回看。
- 流程图在窄屏和宽屏下均可读，布局不导致聊天消息横向溢出。

## 非目标

- 不新增或模拟多个 Agent 的并行分工、评审或汇总。
- 不改变后端 Harness 执行、SSE 事件协议、工具权限或模型提示词。
- 不展示模型的隐藏思维链；节点仅呈现服务端定义的系统执行事件。
- 不在本次增加节点拖拽编辑、流程编辑器或无限画布交互。

## 设计

流程图消费 `HarnessProgressEvent` 列表。普通事件以 `pluginId + stage` 为稳定节点键；工具调用的 `tool_start`、`tool_result` 统一归并到同一工具节点。收到后续对应事件时更新节点，而不是重复创建。为避免虚构并发关系，节点和边按照首次收到事件的顺序排列成线性链路。连线、运行态强调和完成态样式只表示事件顺序与执行状态，不表示数据依赖或 Agent 协作关系。

### 参考官网后的视觉修订

AgentCore 官网首页的 `CollabGraph` 是一段循环播放的演示动画：它以固定时间线驱动多个 Worker 分波启动、节点内文字逐步出现、正交折线上的流动效果和波次闸门。AgentCore 产品内的图则由真实 Agent 执行图数据驱动。GymMind 采用真实 SSE 步骤方案，因此复用官网的动态视觉语言，但不照搬演示用的并行 Worker、计时循环或闸门。

流程区域使用深色点阵画布；事件到达时节点平滑显现，状态更新时节点边框和状态标记过渡高亮；当前运行步骤对应的连线显示沿路径移动的光点/短线，步骤完成或失败后停止该段流动。节点继续按真实事件顺序布局，当前实现无依赖拓扑时保持单链。动效直接由 SSE 步骤状态驱动，不使用固定时长脚本模拟执行过程；遵守 `prefers-reduced-motion`。

同一工具调用的 `tool_start` 和 `tool_result` 是生命周期的开始与结束，应合并为一个稳定工具节点：开始事件显示等待/运行态，结果事件更新同一节点为完成或失败并补上结果数量。详情展开键也使用相同稳定节点 ID，避免状态更新后展开内容丢失。其他 `pluginId + stage` 仍按独立系统步骤处理。

可用原生 Vue 与 SVG/CSS 实现节点、正交连线和路径流动效果，不增加 React、Vue Flow、ELK 等依赖。流程容器适配聊天区域宽度；节点较多时只允许流程画布局部水平浏览，页面本身不得横向溢出。节点、连线和文字布局表达实际步骤顺序，不暗示未由后端提供的数据依赖关系。

点击带有 `details` 的节点可展开原有明细内容；没有明细的节点保持非交互。整体标题栏继续折叠/展开流程区域。历史消息从当前已有的 `processSteps` 持久化数据生成相同图形，不需要新的接口或存储字段。

## 数据与错误处理

复用 `AssistantView.vue` 当前的 SSE `progress` 回调和 `HarnessProgressEvent` 类型。`STARTED`、`RUNNING`、`COMPLETED`、`FAILED` 映射到对应节点样式；聊天流异常仍通过现有 `chat_error` FAILED 事件显示。结束后若后端没有发出额外终态事件，不合成未发生的阶段；整体状态按已有步骤计算。

## 验收标准

1. 收到新的进度事件时能立即新增节点；同一工具的 `tool_start` 与 `tool_result` 更新同一节点，其他同键阶段更新原节点。
2. 节点进入、状态过渡、运行连线流动与实际 SSE 状态对应；开始、运行、完成、失败状态可区分，终态停止流动。
3. 带详情的节点仍可查看知识检索等原有明细；无详情节点不会显示误导性的展开控件。
4. 流程整体可以折叠，历史消息在刷新恢复后仍显示相同节点状态和详情。
5. 手机宽度下流程图可在局部区域浏览，不造成页面级横向滚动或与回答内容重叠。
6. 尊重减少动态效果的系统偏好；前端 TypeScript 构建及现有 SSE/助手相关测试通过。
