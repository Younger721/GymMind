# AI 中心动态执行流程图设计

## 背景

AI 中心当前将 Harness 通过 SSE 推送的执行进度渲染为纵向步骤列表。用户希望改成 AgentCore 协作图所采用的动态节点与连线视觉，以便在回答生成期间直观看到流程进展。

GymMind 当前已有真实的路由、知识检索、插件和 Tool 进度事件，但没有 AgentCore 式的多 Agent 并行执行拓扑。本次只改进现有事件的可视化，不改变执行语义。

## 目标

- 将现有步骤列表改为动态流程图风格，节点随着 SSE 事件到达而出现和更新。
- 明确表达 STARTED、RUNNING、COMPLETED、FAILED 状态，并显示步骤名称、简短摘要和可用结果数量。
- 保留步骤详情展开、流程整体折叠、错误状态和已保存对话中的历史回看。
- 流程图在窄屏和宽屏下均可读，布局不导致聊天消息横向溢出。

## 非目标

- 不新增或模拟多个 Agent 的并行分工、评审或汇总。
- 不改变后端 Harness 执行、SSE 事件协议、工具权限或模型提示词。
- 不展示模型的隐藏思维链；节点仅呈现服务端定义的系统执行事件。
- 不在本次增加节点拖拽编辑、流程编辑器或无限画布交互。

## 设计

流程图消费 `HarnessProgressEvent` 列表。每个不同的 `pluginId + stage` 对应一个稳定节点；收到后续同键事件时更新节点，而不是重复创建。为避免虚构并发关系，节点和边按照首次收到事件的顺序排列成线性链路。连线、运行态强调和完成态样式只表示事件顺序与执行状态，不表示数据依赖或 Agent 协作关系。

可用原生 Vue 与 SVG/CSS 绘制节点、连线和状态动效，不增加 React、Vue Flow、ELK 等依赖。流程容器默认适配聊天区域宽度；节点数量较多时允许在流程区域内水平滚动，页面本身不得横向溢出。节点状态更新时轻量强调当前运行节点，完成或失败后停止运行态动效。

点击带有 `details` 的节点可展开原有明细内容；没有明细的节点保持非交互。整体标题栏继续折叠/展开流程区域。历史消息从当前已有的 `processSteps` 持久化数据生成相同图形，不需要新的接口或存储字段。

## 数据与错误处理

复用 `AssistantView.vue` 当前的 SSE `progress` 回调和 `HarnessProgressEvent` 类型。`STARTED`、`RUNNING`、`COMPLETED`、`FAILED` 映射到对应节点样式；聊天流异常仍通过现有 `chat_error` FAILED 事件显示。结束后若后端没有发出额外终态事件，不合成未发生的阶段；整体状态按已有步骤计算。

## 验收标准

1. 收到新的进度事件时能立即新增节点；同一 `pluginId + stage` 的更新只改变原节点状态和内容。
2. 新链路和后续节点有清晰连线；开始、运行、完成、失败状态可区分，运行态动画只用于进行中的节点/连线。
3. 带详情的节点仍可查看知识检索等原有明细；无详情节点不会显示误导性的展开控件。
4. 流程整体可以折叠，历史消息在刷新恢复后仍显示相同节点状态和详情。
5. 手机宽度下流程图可在局部区域浏览，不造成页面级横向滚动或与回答内容重叠。
6. 前端 TypeScript 构建及现有 SSE/助手相关测试通过。
