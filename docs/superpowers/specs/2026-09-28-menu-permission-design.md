# 菜单权限控制设计

## 目标

角色权限页只配置菜单可见性。拥有菜单权限的角色可以进入该菜单并使用菜单对应的接口功能。系统保留四个内置角色：平台管理员、健身房管理员、教练、会员。

## 默认菜单

- 平台管理员：全部菜单。
- 健身房管理员：首页、AI 助手、知识库、门店运营、训练管理、风险预警、员工·角色、租户设置、账号设置。
- 教练：首页、AI 助手、知识库、训练管理、账号设置。
- 会员：首页、AI 助手、训练管理、账号设置。

## 实现

系统在现有权限表中增加固定的 `menu:*` 权限码。菜单目录维护每个菜单对应的接口权限集合；角色权限保存只接收菜单码，服务层整体替换角色关联，并自动写入菜单码及其接口权限。平台管理员角色不可修改。

前端侧栏和路由守卫统一按菜单码判断。现有按钮和后端服务继续使用接口权限码，由菜单保存时自动展开。健身房管理员不再因为角色身份自动获得全部非平台权限，权限来自角色关联；本健身房数据隔离保持不变。

角色权限目录接口修正为 `/api/v1/roles/permissions`。启动时修复已有权限目录中的空名称和 MySQL 零日期记录，避免 Hibernate 读取权限目录时返回 500。

## 验证

覆盖权限目录修复、菜单权限展开、平台管理员保护和角色菜单可见性；运行后端测试/编译、前端生产构建，并启动前后端检查健康接口和角色权限页请求。
