## 技术实现细节

### 文档处理流水线

```
用户上传文件
    ↓
文件验证（类型、大小）
    ↓
上传到 MinIO（按 userId/文件名存储）
    ↓
创建文档记录（status: PENDING）
    ↓
异步任务开始（status: PROCESSING）
    ↓
┌─────────────────────────────────────┐
│ 1. 从 MinIO 下载文件                │
│ 2. 解析文档（PDF/TXT）              │
│ 3. 清洗文本                          │
│ 4. 分块（512 字符，overlap 50）    │
│ 5. 生成 Embedding（每个 chunk）     │
│ 6. 双写存储                          │
│    ├─ Milvus: 向量 + 元数据         │
│    └─ ES: 全文 + 元数据              │
└─────────────────────────────────────┘
    ↓
更新文档状态（SUCCESS/FAILED）
    ↓
记录 chunk 数量和处理时间
```

### Milvus Collection 结构

```python
Collection: gymmind_knowledge_vectors
Fields:
  - id: Int64 (主键, 自动生成)
  - user_id: Int64 (用户隔离)
  - document_id: Int64 (文档ID)
  - chunk_index: Int64 (chunk 顺序)
  - embedding: FloatVector(1536) (向量)

Index: HNSW
  - M: 16
  - efConstruction: 256
  - Metric: COSINE
```

### Elasticsearch Index 结构

```json
{
  "index": "gymmind_knowledge",
  "mappings": {
    "properties": {
      "user_id": { "type": "long" },
      "document_id": { "type": "long" },
      "document_name": { "type": "text", "analyzer": "smartcn" },
      "chunk_index": { "type": "integer" },
      "chunk_text": { "type": "text", "analyzer": "smartcn" },
      "category": { "type": "keyword" },
      "source_type": { "type": "keyword" },
      "source_url": { "type": "keyword" },
      "created_at": { "type": "date" }
    }
  }
}
```

## 核心特性

### 1. 双重索引架构 ✨
- **Milvus**: 存储向量，用于语义相似度检索
- **Elasticsearch**: 存储全文，用于关键词匹配和过滤
- **同步写入**: 每个 chunk 同时写入两个系统

### 2. 异步处理
- 上传后立即返回，后台异步处理
- 不阻塞用户操作
- 支持大文件处理

### 3. 状态机管理
- PENDING: 等待处理
- PROCESSING: 正在处理
- SUCCESS: 处理成功
- FAILED: 处理失败（记录失败原因）

### 4. 智能分块
- 滑动窗口（512 字符，overlap 50）
- 句子边界检测（中英文标点）
- 词边界检测（避免截断单词）

### 5. 用户数据隔离
- MinIO 按 `user_{userId}/` 分区存储
- MySQL 文档记录包含 userId
- Milvus 向量包含 user_id 字段
- ES 文档包含 user_id 字段
- 所有查询都必须带 userId 过滤

### 6. 失败重试
- 失败文档可重新处理
- 自动清理失败原因
- 重新进入处理队列
