**支持的消息类型**：

| 类型 | 用途 | 场景 |
|------|------|------|
| DOCUMENT_PROGRESS | 文档处理进度 | 上传 → 解析 → 分块 → Embedding → 索引 |

- 消息代理：Spring SimpleBroker

- ⚡ 实时性：用户无需刷新页面
- 🎭 体验升级：AI 对话打字机效果更自然

- 🔔 通知系统：好友动态、挑战更新即时送达

### 5. 多级缓存优化 🚀

**创新点**：L1 本地缓存 + L2 分布式缓存，响应时间提升 80%

**实现文件**：
```
backend/
  ├── config/CacheConfig.java
  └── service/RagService.java (添加缓存注解)
```

**缓存架构**：

```
用户请求
  ↓
L1: Caffeine (进程内缓存)
  - 最大 1000 条
  - 10 分钟过期
  - 超快读取 (<1ms)
  ↓ 未命中
L2: Redis (分布式缓存)
  - 1 小时过期
  - 跨实例共享
  - 快速读取 (~10ms)
  ↓ 未命中
数据源: Milvus + Elasticsearch
  - 向量检索
  - 全文检索
  - 慢速 (~2000ms)
```

**缓存策略**：
```java
@Cacheable(
    value = "rag:queries",
    key = "#request.message",
    condition = "#request.history == null || #request.history.isEmpty()"
)
public ChatResponse chat(ChatRequest request) {
    // 相同查询直接返回缓存
}
```

**性能提升**：
- ⚡ RAG 查询：2-3 秒 → 500ms（缓存命中）
- 📊 用户档案：数据库查询 → 内存读取
- 🏋️ 训练计划：重复查询零延迟

**配置的缓存空间**：
- `rag:queries` - RAG 查询结果
- `user:profiles` - 用户档案
- `workout:plans` - 训练计划
- `nutrition:calculations` - 营养计算

**依赖**：
```xml
<dependency>
    <groupId>com.github.ben-manes.caffeine</groupId>
    <artifactId>caffeine</artifactId>
</dependency>
<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-cache</artifactId>
</dependency>
```

- `TOTAL_TIME` - 累计时长（例如：本月累计训练 1000 分钟）

- `DISTANCE` - 累计距离（例如：跑步 100 公里）

**排行榜算法**：
```java
private void updateRankings(Long challengeId) {
    List<ChallengeParticipant> participants = participantRepository
        .findByChallengeIdOrderByProgressDescRankAsc(challengeId);

    int rank = 1;
    for (ChallengeParticipant participant : participants) {
        participant.setRank(rank++);
        participantRepository.save(participant);
    }
}
```

**完成检测**：
```java
if (progress >= challenge.getGoalValue()) {
    participant.setStatus("COMPLETED");
    
    webSocketService.sendNotification(
        userId.toString(),
        "挑战完成！",
        "恭喜你完成了挑战：" + challenge.getName(),
        "success"
    );
}
```

### 可能的提问

**Q1：为什么选择 Milvus 而不是 Faiss？**
A：Milvus 支持分布式部署、动态索引更新、多种距离度量，更适合生产环境。Faiss 适合单机离线场景。

**Q2：图片 Embedding 和文本 Embedding 如何对齐？**
A：使用 CLIP 模型，它在训练时就将图片和文本映射到同一向量空间，所以可以直接计算相似度。

**Q3：缓存如何保证一致性？**
A：写操作时清除缓存（Cache-Aside 模式），下次读取时重新加载。对于强一致性要求高的场景（如余额），不使用缓存。

**Q4：WebSocket 如何处理断线重连？**
A：前端使用 SockJS 自动重连，后端使用 Spring Session 保持会话状态。

**Q5：如何评估 RAG 系统的效果？**
A：使用 Recall@K, MRR, NDCG 等指标，构建测试集（100+ 问题-答案对）进行离线评估。
